## 4. 用户对 0.1.11 的实测反馈（待处理）

> "武器太靠后了 / 还是没声音 / 你声音命名也要替换原来的 / 别忘了脚本 / 还有声音替换教程再核对"（附第三人称截图：枪身后段插进胸口）

### 4.1 没声音：已查明的情况

- nslog（`R2Vanilla\logs\nslog2026-10-26 22-53-38.txt`）显示 0.1.11 的 11 个音频覆盖全部 `Registering sound event` 并读取成功，事件名与合并后的 keyvalues 完全一致（`R2Vanilla\runtime\compiled\scripts\weapons\mod_original_mp_weapon_car.txt`）。用户机器上其他 CAR 模组都不改声音键。
- 官方教程（https://docs.northstar.tf/Modding/guides/tools/soundmodding/ ）的要求：WAV、48000 或 44100 Hz、**16-bit**、去掉元数据、`<事件>.json` 加同名文件夹、`EventId` 加 `AudioSelectionStrategy`（sequential / random）。我们的文件都符合。
- NorthstarLauncher 源码 `primedev/client/audio.cpp` 的逻辑：只按事件名替换样本指针，不处理循环；`EnableOnLoopedSounds` 已被注释掉。
- **推断**：CAR 的 `burst_or_looping_*` 循环事件（FirstShot、Loop、LoopEnd）被覆盖后实际没有出声。0.1.10 用户听到的"声音不对"其实只是原版的 SecondShot；0.1.11 把 SecondShot 静音后，就完全没声了。

### 4.2 没声音：计划中的修法（尚未动手）

1. 在 `mod_src\keyvalues\scripts\weapons\mp_weapon_car.txt` 加声音键（也就是用户说的"别忘了脚本"）：
   - `"looping_sounds" "0"`
   - `fire_sound_2_player_1p/3p/npc` 保持原版名 `Weapon_Car_SecondShot_1P/3P/NPC`
   - `fire_sound_1_*` 保持弹壳音
2. 在 `build_audio.py` 里把 `Weapon_Car_SecondShot_1P/3P/NPC` 改为**猎兽单发**，不再静音：
   - 1P：`Wpn_ProwlerPDW_1p_WpnFire_FirstShot_Close` 的前约 0.25 s 加淡出，可叠一点 1p Mech 切片；
   - 3P：从 3p `Loop_Close` 切一发（周期 82.8 ms，加约 150 ms 尾音）；
   - NPC：从 3p `Loop_Mid` 切一发。
   - 每发 14.1 rps 会重叠播放，注意总响度，峰值不超过 0.98。
3. `FirstShot`、`Loop`、`LoopEnd` 的覆盖可以删掉（循环关闭后不会播放）。`car_LowAmmo_Shot1` 保留。
4. 请用户在控制台用 `ns_print_played_sounds 1` 开枪，确认实际播放的事件名。这一步在教程里，用户要求核对教程。

音源都在 `audio_raw\apex\audio\*.wav`（float32；`audio_tools.load` 会用 ffmpeg 转换）。Apex 猎兽只有这一套全自动开火音（FirstShot、Loop Close/Mid/Dist、Mech、Tail、LowAmmo）。
